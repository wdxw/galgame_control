# 三维世界核验与画面改进

核验日期：2026-10-01

## 结论

核心功能通过本地验收。本次补上了导入后的自动分析、主世界星图仪入口和物品移动、旋转，修复了保存、重复生成及切换世界时的资源释放问题。画面已向圆润、柔和、有生活感的小岛风格调整。

完整美术计划仍为部分完成：目前使用程序生成的简化模型，原计划的独立 GLB 模型资产库尚未实现；岛面也仍以平面为主，尚无可行走的多层台地。当前画面与动森成品的模型、动画和场景细节仍有差距。

## 功能结果

| 项目 | 核验结果 |
| --- | --- |
| 新游戏世界 | 新游戏关联 VNDB 后可以生成独立世界。配置服务并开启自动分析时，导入或关联成功即在后台分析；关闭开关时不自动请求 AI。 |
| 主世界入口 | 点击星图仪可打开星球目录，目录支持搜索、分页和进入作品世界。 |
| 作品特色 | 10 个测试世界覆盖校园、海岸、科幻、神社、奇幻、悬疑、冬季、庭园 8 类主题。 |
| 村正特色 | `v2016` 的专门规则提供妖刀、刀架、装甲、机械设施、鸟居和洋馆；妖刀作为默认启动入口，场景中有名称标识。 |
| 绑定启动物品 | 重新绑定后仅新入口触发启动请求；建造时点击入口仅选中物品。 |
| 角色与镜头 | 漫游跟随、键盘及点击地面移动、旋转缩放、建造俯视和镜头复位可用。输入搜索文字时不会误移动角色。 |
| 布置 | 新摆放的物品可选中、移动、旋转、删除、撤销；离开画布后回来，预览仍能恢复。 |
| 保存 | 修改立即提交，快速切换世界保留最后一次移动；重启恢复布局；旧版布局可迁移，已删除游戏的旧记录不会阻止其他记录迁移。 |
| 重新分析 | 保留手动布置、移除记录和启动绑定，不重复生成已手动添加的特色物品；重新载入对应主题的灯光和天空。 |
| 分析异常 | 缓存复用、重复请求合并、无效回复回退、旧关联返回结果拒绝写入、损坏缓存恢复均通过测试。 |

新游戏的特色识别受作品资料、分析结果及模型库覆盖范围影响。已有模型可以显示；无法匹配的元素进入待补充列表，可通过特色面板调整。尚未覆盖任意物体的自动建模。

自动分析发送标题、原名、开发商、发售日期、简介和无剧透 VNDB 标签到设置中配置的服务。用户在本次核验中明确授权了导入后的触发行为。密钥使用系统加密；系统加密不可用时只在当前运行中保留。

- 更圆润的树冠、树干、灌木和建筑边缘。
- 草地纹理、铺砖广场、瓦片屋顶和木纹码头。
- 有花瓣的花丛与花坛，较自然的海岸轮廓及水面波动。

- 启动物品的浮动名称标识与更清楚的操作提示。
- 修复部分模型尺寸参数错误导致的车厢、门廊及神社部件缺失。

## 验证范围

- 构建、界面和主进程类型检查通过。
- 世界识别、确定性布局、VNDB 标签过滤测试通过。
- 完整界面验收通过：10 个测试世界、入口切换、布置操作、保存恢复、语言切换、实时画质切换，无渲染错误。
- 新增的分析与存储测试通过：实际导入/关联入口、自动开关、缓存、异常回退、关联变化、手动布局、旧记录和密钥处理。
- 17 项评分功能回归检查通过。

界面测试使用隔离游戏库，VNDB 返回资料和 AI 回复使用测试数据；AI 请求只发送到本机模拟服务，游戏启动由测试替身记录。因此，以上验证覆盖生成、交互和启动请求的连接，不代表已验证真实 AI 服务的识别质量或启动所有本机游戏。测试中的 `v100` 至 `v108` 是测试编号；专门作品规则仅有 `v2016`，未将其他游戏的美术作为引用资产。

## 性能与资源释放

测试机器使用 NVIDIA GeForce RTX 4060 Laptop GPU，高画质，实际世界绘制缓冲区约为 2202 × 1542 像素。

最初仅观察当前画布的几何体和贴图数量，遗漏了旧画布回调的保留。进一步使用实际回收后的堆内存确认了问题，并将缓存改为当前世界所有，在退出时释放。

修复前，同样切换 10 次，进程占用约增加 71 MB，回收后的堆内存增加 11 MB。修复后的首轮复测分别降至 9 MB 和 2 MB，几何体及贴图数量回到基线，页面保留一个画布。

本地性能记录：修复前 `build/bench-OF3bZI/result.json`，修复后的首轮 `build/bench-HkN1Tg/result.json`。

最终复测已改为依据持续平均帧率判定，结果如下：

| 场景 | 平均帧率 | 峰值帧率 |
| --- | ---: | ---: |
| 主世界 | 132.0 | 134.3 |
| 校园 | 112.7 | 116.8 |
| 科幻 | 126.6 | 130.2 |
| 悬疑 | 110.2 | 114.7 |

同一轮切换 10 次后，回收后的堆内存由约 19 MB 到 22 MB，渲染进程占用由约 158 MB 到 164 MB；几何体与贴图数量不增加。该轮通过了几何体、贴图、单画布和堆内存增长不超过 3 MB 的检查。

GPU 进程占用在该轮仍增加约 35 MB。进程占用与当前场景的资源数量需要分别观察；本次短时回收检查不代表已证明长期完全无增长。帧率结论也仅适用于本次机器和测试配置。
